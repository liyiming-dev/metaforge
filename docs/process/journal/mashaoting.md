**遇到的问题和解决过程**（现象 → 原因 → 怎么解决的）

git push 连续失败两次，现象和原因不一样。第一次报 403，`Permission to liyiming-dev/metaforge.git denied to msttt111`，原因是组长发的协作者邀请没点接受，接受后才有写权限。第二次报 `Failed to connect to github.com:443`，直连 GitHub 超时；本机代理端口 7897 开着，给 git 配上 `http.proxy` 之后推送成功。两次都说明本地 commit 成功不等于推送成功。

**今天弄懂的一件事**（用自己的话写，假设是讲给没做过这部分的组员听）

GitHub 的协作权限是“邀请 + 接受”两步，邀请只是挂在那里，不点接受就等于没加。另外本地仓库和远程是两回事：网络断了提交照样成功，只是推不上去，所以要看 push 的提示，不能看 commit 有没有生成。
