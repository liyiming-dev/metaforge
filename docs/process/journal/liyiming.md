**遇到的问题和解决过程**（现象 → 原因 → 怎么解决的）

F5 的“把半截字段名写进视图”在 mock 里点不出来：mock 不校验“视图引用不存在的字段”，真实后端会返回 400。后来用 Playwright 打开编辑页，逐字输入 `contact`，再看 JSON 标签页里的 `views.list.columns`，才发现 `c`、`co`、`con` 都进去了。根因是 `@change` 每按一次键就写一次视图，改成 `@blur` 后解决。

另外合 F1–F3 时先删了 `feat/f1`，GitHub 把基于它的 #2 自动关掉了。恢复 `feat/f1` 分支、重开 #2、把 base 改到 main 才救回来。以后叠加 PR 要“先改下一个的 base，再合并，最后删旧分支”。

**遇到的问题和解决过程**（现象 → 原因 → 怎么解决的）

B2 验收时连续删建同一个模型，第二次删除失败。原因是备份表名只精确到秒，同一秒内删两次会重名；改成精确到毫秒后解决，并补了“连续新建、删除三次”的测试。这个问题单元测试没发现，是真实 MySQL 验收暴露的。

B3 的验收脚本自己也出过错：取查询结果第一行时只截到首字符，报了一个假 FAIL；修脚本后重跑才是真结果。验收脚本也要当代码审查。

**今天弄懂的一件事**（用自己的话写，假设是讲给没做过这部分的组员听）

MySQL 的建表改表不能回滚，所以“保存定义”和“改表”的顺序很重要。我们的做法是先校验、再改表、成功后才保存定义；改表失败时定义还是旧的，表和定义至少对得上。删字段不物理删列，而是改名成 `zz_` 开头留备份，误删还能找回数据。

**遇到的问题和解决过程**（现象 → 原因 → 怎么解决的）

后端启动时报 `Unable to establish loopback connection`，Tomcat 起不来。查下来是本机系统临时目录建不了 Unix domain socket，和项目代码无关。在启动类里规避后正常启动；别的 Spring Boot 项目遇到同样错误，可以加 `-Djdk.net.unixdomain.tmpdir=C:\Windows\Temp`。这件事记进了决策 015。

**今天弄懂的一件事**（用自己的话写，假设是讲给没做过这部分的组员听）

元模型的定义本身也当成数据存：每个模型一份完整 JSON，放在 `meta_model.definition` 里，而不是拆成模型表、字段表、视图表。因为设计器、导入导出、AI 助手都是整份读写，拆表后读一个模型要关联好几张表，目前也没有“按字段查定义”的需求。代价是不能用 SQL 直接查“哪些模型有某种字段”。
