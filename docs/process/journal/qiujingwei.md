## 2026-11-14

**今天做了什么**（任务号和结果）
负责前端 F1（菜单和动态路由）、F2（通用列表页）、F3（通用表单）三个任务。我用 AI 工具辅助写代码，自己负责读需求、定验收点、逐条验收和调试。三个任务都通过 npm run build，推到 feat/f1、feat/f2、feat/f3 三个分支，并开了 3 个 PR。

**遇到的问题和解决过程**
列表组件第一次跑类型检查没过，报 TS2459。我顺着报错查，发现 SortItem 这个类型定义在 @/types/meta 里，而代码从 @/types/api 导入（api 里只是引用了、没导出）。把导入路径改回 @/types/meta 就通过了。这件事让我注意到：共享类型要分清「定义的地方」和「再导出的地方」。

**今天弄懂的一件事**
物料、产品、编码规则三个页面长得完全不一样，但只写了一个 ModelTable 组件。原因：列表显示哪些列、搜索哪些字段，全部来自模型定义里的 views.list（columns / searchFields），所以一套组件能渲染任意模型。这正是这个平台「模型驱动」的核心——改定义不改代码。
