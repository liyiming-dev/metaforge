# 过程记录怎么留

老师看重的是思考和尝试的过程。过程只发生一次，当时不记，事后补不出来，编出来的也经不起问。所以规则只有一条：**当场记，记真实的。**

## 五种记录

| 记录 | 放在哪 | 谁负责 | 证明什么 |
|---|---|---|---|
| 决策记录 | `docs/decisions/` | 每个问题的负责人 | 为什么这样设计，比较过哪些方案 |
| 讨论截图 | `docs/process/screenshots/` | 文档同学归档，所有人配合 | 每个问题讨论过至少 3 次，所有人都参与了 |
| 联调纪要 | `docs/process/meetings/` | 文档同学 | 小组研讨的过程和结论 |
| 学习日志 | `docs/process/journal/` | 每人一份 | 个人的收获，以及怎么使用和判断 AI 的建议 |
| 提交、PR、Issue | GitHub | 所有人 | 每个人实际做了什么 |

## 讨论截图

- 关于项目的讨论都在小组群里进行，不要私聊，这样才截得到。
- 讨论某个问题时，开头带上编号，例如“【002】我倾向每个模型建真实的表，因为……”。
- 文件名是“问题编号-第几次讨论”，例如 `002-1.png`、`002-2.png`。一次讨论有几张图就加字母：`002-1a.png`、`002-1b.png`。
- 和老师的交流、PR 里的评审对话、Issue 里的讨论，截图后同样归档。
- 和具体问题无关的截图（例如环境准备时互相帮忙）用 `misc-日期-序号.png`。

## 学习日志

每人在 `docs/process/journal/` 下有一个自己的文件，从 [TEMPLATE.md](journal/TEMPLATE.md) 复制。每个工作日结束时花十分钟写一条。

写具体的事，不要写感想式的总结。对比一下：

- 没用的写法：“今天学习了动态路由，收获很大。”
- 有用的写法：“刷新页面后 `/app/product` 变成 404。原因是路由是登录后才注册的，刷新时还没注册就开始匹配了。在全局守卫里先加载菜单，再让路由重新匹配一次，解决了。”

## AI 协作反思

老师说过，AI 让写代码变容易了，所以他更想看到我们自己的判断。日志里专门有一栏记这个。值得记的情况：

- AI 给的方案是错的，或者能跑但不合适，你是怎么发现的。
- AI 给了几个方案，你选了哪个，为什么。
- 你没有采纳 AI 的建议，原因是什么。
- 你一开始没看懂 AI 写的代码，后来是怎么弄懂的。

一个例子见 [决策记录 015](../decisions/015-后端启动报loopback错误.md) 的最后一节。
