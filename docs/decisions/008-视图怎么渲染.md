# 008 视图怎么渲染

- 负责人：前端
- 关联任务：F3 通用表单
- 状态：已定
- 最后更新：2026-11-14

## 问题

通用表单要能渲染任意模型的字段，而每个字段的类型不同，对应的输入控件也不同（`string` 用输入框、`enum` 用下拉、`boolean` 用开关……）。要决定的是：在表单组件里用一长串 `v-if` 按字段类型挑控件，还是维护一张「字段类型 → 组件」的注册表，用 `<component :is>` 动态渲染。

## 候选方案

| 方案 | 怎么做 | 好处 | 代价 |
|---|---|---|---|
| A：一长串 v-if | 在 ModelForm 模板里写 `<a-input v-if="field.type==='string'">`、`<a-select v-else-if="field.type==='enum'">`……每种类型一个分支 | 一眼就能看到所有控件，不用额外理解注册表 | 分支越写越长；新增一种字段类型要回到模板改、容易漏改、破坏现有分支；控件细节（如清空发 null）散落各处难以复用 |
| B：字段类型到组件的注册表 | 把每种字段类型抽成一个字段组件（统一 props/事件），在 `fields/index.ts` 建一张 `fieldComponents` 映射，表单里统一 `<component :is="fieldComponents[field.type]">` | 新增类型只加一个组件 + 注册表一行，表单不用动；控件逻辑封装在各自组件里，可复用 | 多一层抽象，初次理解成本略高 |

## 试做和测试

在 `feat/f3` 分支上实现方案 B。要点：

- `fields/` 下的每个字段组件统一 `modelValue / field / disabled` 三个 props 和 `update:modelValue` 事件，各自处理清空、精度、格式等细节。
- `fields/index.ts` 导出 `fieldComponents` 注册表。
- `ModelForm.vue` 用 `<component :is="fieldComponents[field.type]">` 渲染，注册表里没有的类型（manyToOne）显示禁用的输入框占位。

关键片段：

```ts
export const fieldComponents: Partial<Record<FieldType, Component>> = {
  string: StringField,
  text: TextField,
  integer: NumberField,
  decimal: NumberField,
  boolean: BooleanField,
  date: DateField,
  datetime: DateField,
  enum: EnumField,
}
```

## 结论

选了 B（注册表）。决定性的理由：这是模型驱动的平台，字段类型是有限的、以后一定会扩展（图片、文件等）。用注册表，新增一种类型只需「新建一个字段组件 + 在 `index.ts` 加一行」，表单渲染逻辑完全不用动；而 v-if 方案每加一种类型都要回到表单模板里加分支，分支越叠越长、越容易出错。

以后新增一种字段类型（例如图片 `image`）时：
- 方案 B：新建 `ImageField.vue`（统一 props/事件），在 `fields/index.ts` 注册表里加一行 `image: ImageField`；`FieldType` 类型里也要加 `'image'`（这属于契约，需按契约流程改）。表单和列表本身不受影响。
- 方案 A：要在 `ModelForm.vue` 模板里再插一个 `v-else-if="field.type === 'image'"` 分支，还要保证不破坏已有分支顺序。

## 代价和反思

选注册表的代价是：多了一层抽象，要先理解 fieldComponents 才能看懂表单是怎么渲染的。

回头看，新增字段类型除了加组件和映射，还要改 FieldType 类型（属于契约），这步容易漏——F4 加 manyToOne 时就是先改类型和契约再实现的。以后加类型要把「组件、注册表、FieldType」三处一起记。
