## 问题

后端用什么方式访问数据库。上一个项目 ai-agent-project 用的是 MyBatis-Flex，这次骨架里用的是 Spring 自带的 `JdbcTemplate`。要确认这个选择站得住，并且讲得出理由。

这个项目特殊的地方：业务模型（物料、产品）是运行时在页面上定义的，编译的时候根本不知道会有哪些表、哪些列，所以没有对应的 Java 实体类。

## 候选方案

| 方案 | 怎么做 | 好处 | 代价 |
|---|---|---|---|
| A MyBatis-Flex | 沿用上个项目的框架 | 熟悉；固定的表（例如元模型表）可以用实体类 | 它的主要价值是“实体类和表的映射”，而业务表没有实体类，这部分用不上。没有实体类时要用它的 `Db` 加 `Row` 那套接口，等于换了一套不熟的用法；建表改表它不管，还是得自己写 SQL |
| B JPA（Hibernate） | 用实体类和注解 | 生态成熟 | 完全围绕实体类设计，运行时才出现的表基本没法用 |
| C JdbcTemplate | 自己拼 SQL，用 `NamedParameterJdbcTemplate` 绑定参数 | Spring 自带，不加依赖；SQL 完全由自己控制，而这个项目的核心正是“按元模型生成 SQL” | 没有任何自动映射，查询结果是 `Map`，类型转换要自己做；SQL 是自己拼的，防注入要自己负责（见决策 004） |

需要组长核对的一点：上面说 MyBatis-Flex 没有实体类时可以用 `Db` 加 `Row`，这是 Claude Code 的说法，请对照 MyBatis-Flex 的文档确认。上周讨论选题时它说过“MyBatis-Flex 依赖编译期就存在的实体类，所以不能用”，那个说法过于绝对。

## 试做和测试

实际试做就是 B3 的通用数据接口，没有另开一个 MyBatis-Flex 对比工程：

- `DataService` 用 `NamedParameterJdbcTemplate` 对运行时建出来的 `md_*` 表做增删改查；所有值走命名参数，表名/列名只从 `MetaRegistry` 里的定义取。
- `SqlBuilder` 集中生成查询、插入、修改、删除 SQL；`DataApiTest`、`RelationApiTest` 在 H2 上覆盖 CRUD、关联、分页、排序和注入尝试。
- `SqlBuilderTest` 单独覆盖非法字段名、非法排序方向、`in`/`like` 参数等边界。
- 全量测试 119 个通过；真实 MySQL 9.6.0 上跑过 B4/B5 验收。

没有把 MyBatis-Flex 的 `Db` + `Row` 真写成第二套实现。原因不是它做不到，而是它没有解决这个项目的核心问题：表是运行时才知道的，SQL 必须按元模型生成；再引入一层 ORM 只会多一套要维护的写法。

## 结论

选 **C：Spring `JdbcTemplate` / `NamedParameterJdbcTemplate`**。

理由：

1. 业务模型是运行时定义的，没有编译期实体类；ORM 最核心的“实体类 ↔ 表”映射用不上。
2. 这个项目的核心正是“按元模型生成 SQL”。表名、列名、条件、排序都由 `SqlBuilder` 从校验过的模型定义生成，SQL 完全可控，也方便针对注入写单元测试（决策 004）。
3. Spring Boot 自带，不增加依赖；事务、连接池、异常转换已经够用。
4. MyBatis-Flex 没有实体类时可以用 `Db` + `Row` 做动态查询，但这会引入一套组员不熟的新 API 和额外依赖；元模型表只有 `meta_module`、`meta_model` 两张，为它们引入 ORM 的收益也很小。
5. JPA 完全围绕实体类，运行时才出现的表基本没法用，直接排除。

准确说法不是“MyBatis-Flex 做不到”，而是“在这个场景下它的收益不值得”。如果以后做的是模型固定、实体很多的管理系统，ORM 会更省事。

## 代价和反思

- 没有自动映射：数据库行要自己转成 `Map`/JSON，多对一还要额外拼 `{id,label}`；这些代码集中在 `DataService`/`SqlBuilder`，没有散落到各个接口。
- SQL 自己拼：防注入要自己负责。我们用“标识白名单 + 参数绑定 + 操作符 switch + 拼前再校验”四道规则，见决策 004；`SqlBuilderTest` 覆盖非法输入。
- 建表和改表也要自己写：`DdlBuilder`/`SchemaSync` 和查询 SQL 是两套代码，模型改动时要同时检查；这是动态模型的固有成本。
- 没有 ORM 的关联加载、缓存、懒加载；本项目不需要，BOM 的 `{id,label}` 用一次 `IN` 查询批量取，够用且 SQL 条数固定。
- AI 最初把“MyBatis-Flex 依赖实体类”说得过绝对；组长核对文档后修正为“可以用 Db+Row，但在动态模型场景收益不够”。这提醒我们：AI 的框架比较也要自己查文档，不能直接当结论。
