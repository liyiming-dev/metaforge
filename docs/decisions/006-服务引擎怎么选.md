# 006 服务引擎怎么选

- 负责人：后端（组长）
- 关联任务：B5
- 状态：已定
- 最后更新：2026-11-20

## 问题

B5 要让开发者写的脚本在 JVM 里执行，包括手动服务、`beforeCreate` 等生命周期钩子。需要决定：

1. 用哪个脚本引擎：Groovy、AviatorScript，还是 Spring 自带的 SpEL。
2. 脚本里能访问什么：只给 `record`、`params`，还是把 `JdbcTemplate` 直接给脚本。
3. 怎么限制脚本做危险的事，以及死循环怎么办。

## 候选方案

| 方案 | 怎么做 | 好处 | 代价 |
|---|---|---|---|
| A. Groovy 4.0.33 | JSR-223 `ScriptEngine`，脚本直接调 `db.get(...)` | Java 风格，循环/多语句自然；组员容易看懂 | 依赖 7.4 MB；沙箱要自己配 `SecureASTCustomizer`/`SandboxTransformer`；JSR-223 没有自带执行超时 |
| B. AviatorScript 5.4.4（选） | 注册受控函数 `db.get/db.increment/db.today`，脚本写 `db.get(...)`；开启 sandbox | 依赖 0.6 MB；启动和执行快；内置 sandbox、`EVAL_TIMEOUT_MS`、`MAX_LOOP_COUNT`；脚本仍保持 `db.get` 的可读写法 | 要在 Java 侧写一层函数适配；反射调用在 sandbox 下会被拦，不能直接把任意 Java 对象丢给脚本 |
| C. SpEL | Spring 自带 | 不用加依赖 | 表达式语言，循环/多语句支持弱，不适合写“生成编码”这种脚本；没有独立沙箱 |

## 试做和测试

试做工程用同一个 `Db` 替身（`get`、`increment`、`today`），两个引擎各跑两遍，输出应为 `MAT-202611200001`、`MAT-202611200002`。

### Groovy

```groovy
def rule = db.get('code_rule', params.ruleId)
def serial = db.increment('code_rule', rule.id, 'current_serial')
def digits = serial.toString()
while (digits.length() < rule.serial_digits) { digits = '0' + digits }
return rule.prefix + db.today(rule.date_format) + digits
```

实测（Groovy 4.0.33，Java 21）：

```text
groovy.first=MAT-202611200001
groovy.second=MAT-202611200002
groovy.cold2_ms=855
groovy.compile_ms=12
groovy.eval1000_ms=187
```

依赖：`org.apache.groovy:groovy:4.0.33` 7.4 MB + `groovy-jsr223:4.0.33`。

### AviatorScript

方式一（反射，不推荐用于 sandbox）：

```javascript
let rule = get(db, "code_rule", params.ruleId);
let serial = increment(db, "code_rule", rule.id, "current_serial");
...
```

需要 `JavaMethodReflectionFunctionMissing`；开启 sandbox 后实测被拦：

```text
aviator.sandbox=BLOCKED FunctionNotFoundException: Function not found: get
```

方式二（受控函数，选这个）：B5 把 `db.get`、`db.increment`、`db.today` 注册成 Aviator 函数，脚本写：

```javascript
let rule = db.get("code_rule", params.ruleId);
let serial = db.increment("code_rule", rule.id, "current_serial");
let digits = "" + serial;
while (string.length(digits) < rule.serial_digits) {
  digits = "0" + digits;
}
return rule.prefix + db.today(rule.date_format) + digits;
```

实测（Aviator 5.4.4，Java 21，sandbox 开启）：

```text
aviator.first=MAT-202611200001
aviator.second=MAT-202611200002
aviator.cold2_ms=11
aviator.compile_ms=0
aviator.eval1000_ms=38
sandbox.function.first=MAT-202611200001
sandbox.function.second=MAT-202611200002
```

依赖：`com.googlecode.aviator:aviator:5.4.4` 0.6 MB。

### 对比结论

| 维度 | Groovy | Aviator（受控函数） |
|---|---|---|
| 冷启动 | 约 0.9 秒 | 约 11 ms |
| 1000 次执行 | 约 187 ms | 约 38 ms |
| 包大小 | 7.4 MB | 0.6 MB |
| 沙箱 | 要自己配，且没有自带超时 | 内置，sandbox 下受控函数可用 |
| 脚本可读性 | 最接近 Java | 用了 `db.get` 函数后也接近 Java，但语法要学 |

性能不是决定性因素（服务是人点按钮触发的），**决定因素是沙箱**：Aviator 内置的 sandbox、执行超时和循环上限，正好回答 006 的“怎么限制危险脚本/死循环”；Groovy 需要自己补一套，代码更多、更容易漏。

## 结论

选 **AviatorScript 5.4.4 + 受控函数**：

1. B5 在 Java 侧注册 `db.get`、`db.increment`、`db.today` 等函数，脚本不直接接触 `JdbcTemplate`。
2. 开启 Aviator sandbox，设置执行超时和循环上限。
3. 脚本上下文保留 `record`、`params`；生命周期钩子能读/改 `record`，手动服务能拿 `params`。
4. 没选的 Groovy 留在 `spike/006-groovy` 分支；Aviator 的反射试做留在 `spike/006-aviator/generate.av`，受控函数版是 `generate-functions.av`。

## 代价和反思

- Aviator 的语法不是 Java，组员要学；但“生成编码”这类脚本只有几行，成本可控。
- 受控函数要写适配层，不能把任意 Java 对象给脚本；这是有意的限制。
- 性能数据只是试做环境，不是生产基准；真正的收益是沙箱和包大小。
- 如果以后脚本需要复杂业务逻辑（大段循环、调用多个服务），Aviator 可能不如 Groovy 顺手；到时再评估，不现在过度设计。
