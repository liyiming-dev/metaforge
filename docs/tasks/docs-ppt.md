# 文档、测试、PPT、视频任务

> 这份是组长留作参考的完整计划，不直接发给文档同学。发给文档同学的是 [docs/handoff/文档任务包.md](../handoff/文档任务包.md)。

你负责的东西决定了老师最看重的那部分分数：老师说过，思考与收获比项目完成度更重要，而思考和收获只能通过文档、PPT、视频被看见。

提交时一共五样东西：演示视频、汇报 PPT、项目开发过程文档、项目开发文档、源代码。前四样由你统稿，内容由三个人一起提供。

你的工作分两段：

- **这个周末（11/14 至 11/15）：** 当场记录。讨论、试错、联调都只发生一次，过后补不出来。同时写需求分析和可行性分析，准备测试用例。
- **之后两周：** 测试、画图、统稿、做 PPT、录视频。

所有文档先用 Markdown 写在仓库的 `docs/` 下并提交，最后再转成 Word。这样你的每一次提交都是参与的证据。

## D5 用平台搭出 MES（联调 2 之后）

**目标：** 课题第 4 条要求“需要在这个平台上面做一个简单的管理系统”。由你这个没写平台代码的人，只用设计器页面把它配出来，这是最有说服力的证明。预计 2 小时。

**步骤**

1. 让后端同学清空元模型，从空白开始。
2. 对照 [docs/contract/samples/mes.json](../contract/samples/mes.json)，在设计器页面里手工配置：两个模块，四个模型（物料、产品、产品 BOM、编码规则）以及它们的字段、视图、服务。不要用导入功能。
3. 每一步都截图。这些截图后面用三次：用户操作说明、PPT、视频脚本。
4. 录入演示数据：2 条编码规则、5 个物料、2 个产品，每个产品 2 到 3 条 BOM。
5. 配置过程中觉得不顺手、看不懂的地方，全部记下来，提 Issue 给前端。
6. 写决策 014：示例系统为什么选 MES。提示：它和课上用 IIDP 做的案例是同一个题目，可以直接对比两种做法。

**产出：** `docs/dev-doc/images/mes/` 下的截图；`docs/decisions/014-示例系统为什么选MES.md`

**验收标准**

- [ ] 配完后用导出功能得到的 JSON，和 `mes.json` 相比，模块、模型、字段都一样；有差别的地方能说出原因。
- [ ] 有从空白到完成的全过程截图。
- [ ] 至少提了 3 条易用性方面的 Issue。
- [ ] 四个模型都能增删改查，新增物料时编码自动生成。

## D6 设计文档（11/16 至 11/18）

**目标：** 写出项目开发文档的第三章。学院的要求是：概要设计里要有组织结构图或分析类图，详细设计里要有类图、活动图、时序图。

**步骤**

1. 找后端和前端要素材。他们的任务 B8 和 F8 里写了要给你什么。
2. 概要设计：
   - 系统架构图：浏览器、前端、后端、数据库四层；标出“设计态”（定义元模型）和“运行态”（使用业务功能）两条路径。
   - 功能结构图：平台有哪些功能模块。
   - 分析类图：模块、模型、字段、服务、视图这几个概念之间的关系。依据是 [meta-model.md](../contract/meta-model.md)。
3. 详细设计：
   - 类图 2 张：后端核心类；字段类型的策略类。
   - 时序图 2 张：“开发者保存一个模型”和“业务用户查询一页数据”。
   - 活动图 1 张：“新建一条记录”，包含前置钩子、校验、写库、后置钩子。
   - 数据库设计：元模型表的结构，以及业务表的命名和列类型规则。
   - 接口设计：引用 `docs/contract/api.md`，不用重抄。
4. 每张图画完，发给对应的同学确认类名、方法名和代码一致。确认的对话截图留下。

**产出：** `docs/dev-doc/03-项目设计.md`，图的源文件和 PNG 都放进仓库。

**验收标准**

- [ ] 有分析类图、至少 2 张类图、至少 2 张时序图、至少 1 张活动图。
- [ ] 每张图都经过后端或前端同学确认，图里的名字和代码一致。
- [ ] 所有图风格统一，都有编号和标题。

## D7 两份文档成稿（11/19 至 11/22）

**项目开发文档**的目录，对应学院的要求：

1. 需求分析（D2）
2. 项目可行性分析（D3）
3. 项目设计：概要设计和详细设计（D6）
4. 项目实现：后端和前端各写自己的部分，你统稿。每个关键功能配界面截图和一小段代码。
5. 测试（D4）
6. 项目分工说明：每个人做了什么、怎么合作的。配上 GitHub 的贡献统计截图和 PR 列表截图。
7. 学习体会与项目进展：每人一段学习体会，加上完成情况和不足。

**项目开发过程文档**的目录：

1. 问题清单：来自 `docs/decisions/README.md` 的那张表。
2. 每个问题一节，固定写这几项：问题是什么、有哪些候选方案、试做和测试的过程、讨论过程（至少 3 张截图）、最后的选择和理由、回头看的反思。内容来自各人写的决策记录，你负责把格式统一、把截图配齐。
3. AI 协作反思：汇总三个人学习日志里“AI 给了不合适的方案，我是怎么发现和处理的”这类记录。
4. 每个人的收获。

**步骤**

1. 把 Markdown 整理成 Word：封面、目录、页码、图表编号。
2. 发给另外两人通读，意见在群里说，截图留下。

**验收标准**

- [ ] 对照学院《项目作品要求》逐条检查：需求分析、可行性分析、项目设计、项目实现、项目分工说明都有。
- [ ] 过程文档里每个问题都有至少 3 次讨论的截图。
- [ ] 三个人都通读过，并且在群里确认。

## D8 汇报 PPT（11/21 至 11/23）

**目标：** 老师最想听的是“为什么这样设计”，所以 PPT 的主体是设计决策，不是功能清单。建议 15 到 18 页。

**建议的结构**

1. 封面：项目名、组员
2. 选题：课题 4 的要求，我们的目标
3. 为什么自己造一个平台：先在课上用 IIDP，再追问它是怎么工作的
4. 两类用户和他们的需求
5. 总体架构：设计态和运行态
6. 到 11. 关键设计决策，每页一个。固定的版式：问题 → 候选方案 → 我们的选择 → 理由 → 付出的代价。从问题清单里挑 5 到 6 个最有话可讲的
7. 演示：截图或嵌入视频片段
8. 对比：和 IIDP 的做法比，和老师的示范模板比
9. AI 是怎么用的：哪些交给了 AI，哪些是我们自己判断的，AI 错在哪
10. 遇到的问题和解决过程
11. 每个人的收获
12. 分工

**验收标准**

- [ ] 每个设计决策页都写了候选方案和选择的理由。
- [ ] 每页文字不超过 6 行，能用图就不用字。
- [ ] 三个人都审过，各自确认了讲自己那部分的页面。

## D9 演示视频（11/23 至 11/26）

**目标：** 一段能让没看过代码的人相信“四条要求都做到了”的视频。建议 6 到 8 分钟。

**步骤**

1. 先写脚本，表格形式：序号、画面、旁白、时长、对应课题第几条要求。建议的顺序：

   | 片段 | 内容 | 时长 |
   |---|---|---|
   | 开场 | 这是什么，解决什么问题 | 30 秒 |
   | 现场建模 | 在设计器里新建“供应商”模型，不重启，菜单出现，增删改查 | 2 分钟 |
   | MES 示例 | 物料、产品和 BOM 明细、新增物料时编码自动生成 | 2 分钟 |
   | 服务 | 修改一段脚本，立刻生效 | 1 分钟 |
   | AI 助手 | 一句话生成模型，确认后生效（做了才录） | 1 分钟 |
   | 背后的设计 | 架构图，讲 2 个关键决策 | 1.5 分钟 |
   | 结尾 | 收获 | 30 秒 |

2. 脚本发到群里，三个人确认。
3. 准备干净的演示数据。录之前关掉无关的窗口和通知，浏览器隐藏书签栏。
4. 用 OBS 或系统自带的录屏录制，分辨率 1080p。可以分段录，再剪到一起。旁白可以后期配。

**验收标准**

- [ ] 脚本里课题的四条要求每条都有对应的片段。
- [ ] “现场建模”这一段是一个连续的镜头，中间没有剪辑，能看出确实没有重启。
- [ ] 声音清楚，字能看清。
- [ ] 三个人都看过成片。
