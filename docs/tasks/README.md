# 任务总览

MetaForge（元铸）是我们组《中级软件设计实作》课题 4 的作品：一个模型驱动的低代码平台，并在平台上搭一个小型 MES。提交截止 **2026-11-29**。

## 每个人看哪份文件

| 角色 | 任务文件 | 一句话职责 |
|---|---|---|
| 后端（组长） | [backend.md](backend.md)，环境见 [00-setup.md](00-setup.md) | 元模型、动态建表、通用接口、服务引擎；最后评审所有人的代码 |
| 前端 | [前端任务包](../handoff/前端任务包.md) | 动态路由、通用列表和表单、模型设计器、界面设计 |
| 文档 | [文档任务包](../handoff/文档任务包.md)；D5 以后的要求暂存在 [docs-ppt.md](docs-ppt.md) | 过程记录、需求和设计文档、测试、PPT、视频 |

前后端怎么对接，只看 [docs/contract/](../contract/README.md)。

## 发给组员的任务包

前端和文档同学各只需要一个文件，在 `docs/handoff/` 下。每份任务包的开头一页是人要做的几步，后面是写给 AI 的完整说明，可以整个发给 AI 照着做。任务包是自包含的：接口契约和现有代码都复制在里面，不用再看别的文件。

任务包不要直接改。它们由 `docs/handoff/` 下的两个模板生成，改了模板、契约或骨架代码之后，在仓库根目录重新生成，再把新文件发给组员：

```bash
node docs/handoff/build.mjs
```

## 课题要求和我们的对应

课题 4 原文有四条要求。评分标准是“功能界面完整度 50%，功能逻辑完成度 50%”，所以四条都要有能演示的东西。

| 课题原文 | 我们做什么 | 在哪个任务里验收 |
|---|---|---|
| 1. 使用熟悉的技术开发一个模型驱动开发的低代码平台 | Spring Boot + MySQL + Vue 3 | 全部 |
| 2. 开发者可以通过定义模型、属性、服务、视图 | 模型设计器：定义模块、模型、字段、视图、脚本服务 | B1、B5、F5 |
| 3. 平台可以动态加载元模型定义信息，动态生成 api、动态渲染视图。前端需要通过元模型信息，动态生成前端路由 | 改了模型不用重启；任意模型自动有增删改查接口；通用列表页和表单页；按菜单动态注册路由 | B2、B3、B6、F1、F2、F3 |
| 4. 需要在这个平台上面做一个简单的管理系统 | 用设计器配出小型 MES：物料、产品、产品 BOM、编码规则 | D5 |

## 老师看重什么

老师当面说过：学习过程中的思考与收获比项目完成度更重要；尝试的过程比结果重要。所以每个任务除了“验收标准”，还有一栏“要记录的思考”。这一栏和代码同等重要，要当场写，事后补不出来。怎么记见 [docs/process/README.md](../process/README.md)。

完成度的目标：比老师示范的模板高一些。后端功能更完善（关联关系、脚本服务、不重启生效），前端更有设计感。

## 谁等谁

前端不用等后端。`frontend/src/mock` 按契约实现了一个假后端，前端周六全天对着它开发，联调时把 `VITE_USE_MOCK` 改成 `false` 再对接真实后端。

## 两次联调

联调时三个人都在，文档同学记纪要（模板见 `docs/process/meetings/`）。

**联调 1（周六晚）：最小闭环。** 前端切到真实后端，下面每条都要现场演示通过：

- [ ] 导入 `docs/contract/samples/mes.json` 后，左侧菜单出现“生产管理”和“基础设置”
- [ ] 物料列表能显示、搜索、翻页
- [ ] 能新增、编辑、删除物料；名称不填、编码重复时，错误提示显示在对应的输入框下面
- [ ] 用接口新建一个模型，刷新页面后菜单里出现它，并且能增删改查。全程不重启后端

**联调 2（周日晚）：四条要求都能演示。**

- [x] 在设计器里新建一个模型，不刷新页面菜单就出现，能增删改查（用 `demo_customer` 验证）
- [x] 产品的表单里有“BOM 明细”标签页，能增删 BOM；物料下拉框能搜索（本次只回归，未增删）
- [x] 新增物料时不填编码，保存后自动得到按规则生成的编码（`MAT-20261123-0006`）
- [x] 编码规则列表上能点“生成编码”（`MAT-20261123-0007`）
- [x] 改一个模型（加字段、改视图）后立刻生效，不重启（`demo_customer` 加 `address` 字段）

## 每个任务的固定流程

1. 从最新的 `main` 开一个分支，名字带任务号，例如 `feat/b1-meta-storage`。
2. 按任务文件里的“步骤”做。
3. 对照“验收标准”逐条自测，在 PR 描述里贴结果或截图。
4. 把“要记录的思考”写进决策记录或自己的学习日志。
5. 提 PR，在群里说一声。组长评审，有意见就在 PR 里讨论，由本人修改。
6. 合并后再开下一个任务的分支。

为什么要这样做、分支和提交信息怎么写，见仓库根目录的 [CONTRIBUTING.md](../../CONTRIBUTING.md)。
