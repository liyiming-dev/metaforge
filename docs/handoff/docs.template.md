### 项目是什么

项目名是 MetaForge，中文名“元铸”。它是一个模型驱动的低代码平台。

- “模型”是对一种业务对象的描述，例如“物料”。一个模型包含：字段（例如物料编码、物料名称）、视图（列表显示哪些列、表单怎么排）、服务（一段脚本，例如自动生成编码）。这些描述统称“元模型”。
- 开发者在平台的“模型设计器”页面上定义模型。保存后，平台自动在数据库里建表，自动提供这个模型的增删改查接口，前端自动出现菜单、列表页和表单页。整个过程不写代码、不重启。
- 为了证明平台可用，小组在平台上配置了一个小型 MES（制造执行系统）作为示例。

和课上的 IIDP 的关系：课上是作为使用者用 IIDP 开发 MES。IIDP 把模型的信息写在 Java 代码的注解里，改了要重新编译才生效。MetaForge 把同样的信息存成数据，运行时就能改。示例选 MES，是因为它和课堂案例是同一个题目，可以直接对比两种做法。

### 两类用户

- **平台开发者**：用模型设计器定义模块、模型、字段、视图、服务的人。
- **业务用户**：使用搭建出来的管理系统的人，例如在 MES 里录入物料、维护产品 BOM 的人。

### 功能清单

平台开发者用的功能：

- FR-01 模块管理：新增、修改、删除模块，模块有标识、显示名、图标、排序。模块下还有模型时不能删除。
- FR-02 新建模型：填写标识、显示名、所属模块。标识必须以小写字母开头，只含小写字母、数字、下划线，最长 30 位；不合规则时当场提示。
- FR-03 定义字段：支持 10 种类型（单行文本、多行文本、整数、小数、是否、日期、日期时间、枚举、多对一、一对多）。每个字段可以设置必填、唯一、只读、默认值。
- FR-04 枚举字段至少要有一个选项，否则不能保存。
- FR-05 定义视图：列表显示哪些列及顺序、搜索字段、默认排序、表单分组。不定义时系统自动生成默认视图。
- FR-06 定义服务：给模型添加脚本服务，可以选择触发时机：手动调用、新建前、新建后、修改前、修改后、删除前。
- FR-07 保存模型后，不重启系统、不刷新页面，左侧菜单立即出现这个模型。
- FR-08 修改模型：新增的字段立刻可用，已有数据不丢失；已保存字段的类型不能修改。
- FR-09 删除模型：模型被其它模型的关联字段引用时不能删除，并提示被谁引用。
- FR-10 导出和导入：把全部元模型导出成 JSON 文件；导入 JSON 文件恢复元模型。
- FR-11（加分项，可能不做）AI 助手：输入一句话描述，生成模型定义的预览，用户确认后才生效。

业务用户用的功能：

- FR-12 菜单：按模块分组显示模型，点击进入模型的列表页。每个模型有自己的页面地址，刷新后仍停留在该页。
- FR-13 列表页：按视图定义显示列。枚举显示中文选项，是否类型显示“是”或“否”，关联字段显示对方的名称。
- FR-14 搜索：文本模糊匹配，枚举精确匹配；重置后恢复全部数据。
- FR-15 分页，点击列头排序。
- FR-16 新增记录：表单按视图定义分组排列，并带出字段的默认值。
- FR-17 必填校验：必填字段没填时，在该字段下方提示，不能保存。
- FR-18 唯一校验：唯一字段的值和已有记录重复时，在该字段下方提示“已存在”。
- FR-19 只读字段不能填写，例如由系统自动生成的编码。
- FR-20 编辑记录：带出原值，保存后列表更新。
- FR-21 删除记录：需要确认；记录被其它记录引用时不能删除，并说明被谁引用。
- FR-22 多对一字段：用可搜索的下拉框选择关联的记录。
- FR-23 一对多：在主记录的表单下方用标签页显示子表，可以增删改子记录，例如产品的 BOM 明细。新建的主记录要先保存，才能添加子记录。
- FR-24 手动服务：显示成按钮，点击后执行并显示结果，例如编码规则的“生成编码”。
- FR-25 自动服务：新增物料时不填编码，保存后系统按编码规则自动生成编码。

平台自身的特性：

- FR-26 元模型的任何修改都不需要重启后端。
- FR-27 任意模型自动拥有增删改查接口，不需要为它单独写代码。
- FR-28 接口收到非法的字段名或排序方式时返回错误，不会被用来执行恶意的数据库语句。
- FR-29 出错时，错误信息能定位到具体的字段。

### MES 示例

两个模块：“生产管理”和“基础设置”。四个模型：

| 模型 | 所属模块 | 字段 | 说明 |
|---|---|---|---|

### 已知的技术难点和计划的对策

这些是计划中的做法，实际做法以组长和前端同学的确认为准。

| 技术难点 | 计划的对策 |
|---|---|
| 运行时建表、改表。MySQL 的建表改表语句执行后不能回滚 | 先把模型定义完整校验一遍，全部通过才执行；删除字段时不删除数据库里的列 |

## D2 需求分析

### 要完成的（AI 读）

分两轮做。

**第一轮：出调查问卷。** 用户说“完成任务 D2”而还没有给你调查回答时，只做这一轮。

输出两份问卷，每份 5 道题，写成可以直接复制到群聊里的纯文本：

- 问卷 A 发给“平台开发者”。被调查的是另外两位组员，他们在课上用 IIDP 开发过 MES。题目围绕：定义一个新的业务对象希望怎么操作、改了字段以后能不能接受重启、希望平台自动做哪些事、哪些地方最容易出错。
- 问卷 B 发给“业务用户”。被调查的是一位用过课堂 MES 案例的同学。题目围绕：录入物料和产品时哪些信息希望自动填、怎样查找记录、填错了希望怎么被提醒、一个产品的物料清单希望在哪里维护。

题目要问具体的情形，让回答能直接变成一条需求。不要问“你觉得系统重要吗”这类题。

**第二轮：写完整的需求分析。** 用户把收集到的回答发给你之后做。输出文件 `docs/dev-doc/01-需求分析.md`，章节如下：

1. 需求获取
   - 1.1 调查对象和方式。
   - 1.2 需求调查表。列：题号、问题、回答人、回答原文、由此得到的需求编号。回答原文照抄用户给的，不要改写。
