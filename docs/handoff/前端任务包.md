# 第一部分：你要做的事

你负责平台的前端页面。代码交给 AI 写，你负责三件事：**把任务发给 AI，照着清单验收，提交**。

## 1. 准备（只做一次，约 15 分钟）

1. 安装 Git 和 Node.js。Node.js 要 20.19 以上或 22.12 以上，用 `node -v` 确认。
2. 配置 Git 身份。邮箱必须是你注册 GitHub 用的那个，否则你的提交在 GitHub 上不算你的。

   ```bash
   git config --global user.name "你的名字"
   ```

   ```bash
   git config --global user.email "你注册 GitHub 用的邮箱"
   ```

3. 下载代码并启动。仓库地址找组长要。

   ```bash
   git clone 组长给你的仓库地址
   ```

   ```bash
   cd metaforge/frontend
   ```

   ```bash
   npm install
   ```

   ```bash
   npm run dev
   ```

4. 浏览器打开 <http://localhost:5173>。看到“环境检查”，其中“页面数据来源”写着“前端内存 mock（示例里有 4 个模型）”，就成功了。

“后端连接”那一行显示红色是正常的。这个周末你不需要启动后端，页面用的是内置的假数据。假数据在浏览器内存里，**刷新页面就会恢复成初始状态**，这也是正常的。

一次只做一个任务，按 F1、F2、F3 的顺序来。下面用 F1 举例，做别的任务时把 `f1` 换成对应的编号。

**第二步：把任务发给 AI。** 两种方式选一种：

然后打开 GitHub 上的仓库页面，点页面上方的 “Compare & pull request”，再点 “Create pull request”，把链接发到群里。组长会看，有意见会写在这个页面上，你把意见原样发给 AI 让它改，改完再执行一遍第四步的三条命令。

# 第二部分：给 AI 的总说明

从这里开始是写给 AI 的。

你在帮一位大学生完成课程作品的前端。用户会说“完成任务 F1”这样的话，你按第三部分对应的任务卡实现。用户不一定熟悉前端，所以你要一次把事情做对，并且把做了什么讲清楚。

## 项目是什么

MetaForge 是一个模型驱动的低代码平台。开发者在页面上定义“模型”（例如物料、产品），每个模型有字段、视图和服务；平台后端按定义建表并提供通用的增删改查接口；前端按定义渲染菜单、列表页和表单页。改了定义不用改代码、不用重启。

前端要做的核心是三件事：

1. 根据接口返回的菜单，运行时注册路由（动态路由）。
2. 用同一套通用的列表页和表单页，显示任意模型的数据。
3. 一个“模型设计器”，让开发者在页面上定义模型。

## 技术栈

Vue 3（组合式 API，`<script setup lang="ts">`）、TypeScript（严格模式）、Ant Design Vue 4、Pinia、Vue Router 5（用法和 4 相同）、Vite、axios、dayjs。具体版本见第四部分的 `package.json`。

- Ant Design Vue 已经全局注册，模板里直接用 `a-button`、`a-table` 这些组件，不用 import。
- 图标从 `@ant-design/icons-vue` 按需 import。
- TypeScript 开了严格检查，用下标访问数组或对象时结果可能是 `undefined`，要判空。

## 硬性规则

违反任何一条都算没完成。

1. **一次只做用户指定的那一个任务。** 不要提前实现后面任务的内容。
2. **不能写死任何业务模型。** 除了 `src/mock` 目录，代码里不能出现 `material`、`product`、`product_bom`、`code_rule` 这类具体的模型名或它们的字段名。列表有哪些列、表单有哪些字段，全部来自接口返回的模型定义。
3. **不要修改这些文件和目录：** `src/api/`、`src/types/`、`src/mock/`、`docs/contract/`、`vite.config.ts`、各个 `tsconfig` 文件。也不要新增依赖。如果你认为它们有错，或者任务确实需要改它们，停下来告诉用户，让用户去问组长。
4. **调接口只用 `src/api/` 里已有的函数**（`metaApi`、`dataApi`、`callService`、`generateByAi`），类型只用 `src/types/` 里已有的定义。不要自己创建 axios 实例，不要自己拼接口地址。
5. **错误提示不要重复弹。** `src/api/request.ts` 在请求失败时已经弹出全局提示（有字段级错误时除外）。页面里捕获 `ApiError`，只是为了显示 `fieldErrors` 或者恢复界面状态。
6. 界面文字和代码注释都用中文。
7. 文件放在约定的位置：页面放 `src/pages/`，可复用的组件放 `src/components/`，字段组件放 `src/components/fields/`，Pinia 的 store 放 `src/stores/`。任务卡里写了文件名的，必须用那个文件名，因为后面的任务会引用它。
8. 如果你能读取仓库里的文件，以仓库里的实际文件为准。第四部分是它们的副本，可能比仓库旧。

## 完成一个任务后怎么回复

如果你能执行命令，先在 `frontend` 目录下运行 `npm run build`，确认没有类型错误和构建错误。然后按下面的格式回复：

## F1 菜单和动态路由

### 要实现的（AI 读）

新建 `src/stores/menu.ts`、`src/pages/ModelListPage.vue`；修改 `src/router/index.ts`、`src/layouts/BasicLayout.vue`。

1. `src/stores/menu.ts` 导出 `useMenuStore`：
   - 状态：`menus`（`MenuNode[]`）、`loaded`（布尔）。
   - 方法 `load()`：调用 `metaApi.menus()`，保存到 `menus`。然后对每个叶子节点（同时有 `model` 和 `path` 的节点）调用：

     ```ts
     router.addRoute('layout', {
       path: node.path,
       name: `app-${node.model}`,
       component: () => import('@/pages/ModelListPage.vue'),
       props: { model: node.model },
       meta: { title: node.displayName },
     })
     ```

     把注册过的路由名记在一个数组里。最后把 `loaded` 设为 `true`。
   - 请求失败时也要把 `loaded` 设为 `true`、`menus` 设为空数组，否则路由守卫会死循环。
   - 方法 `reload()`：对记下的每个路由名调用 `router.removeRoute`，清空这个数组，然后重新执行加载逻辑。任务 F5 会用到。
   - 这个文件要 import `@/router`，而 `src/router/index.ts` 也要 import 这个 store。两个文件互相 import 没有问题，因为双方都只在函数内部使用对方。
2. 在 `src/router/index.ts` 里加全局前置守卫：

   ```ts
   router.beforeEach(async (to) => {
     const menuStore = useMenuStore()
     if (!menuStore.loaded) {
       await menuStore.load()
       // 动态路由刚注册好，让这次跳转重新匹配一遍
       return to.fullPath
     }
   })
   ```

   为此要把文件末尾的 `export default createRouter(...)` 改成先赋值给变量 `router`，加完守卫再 `export default router`。
3. 修改 `src/layouts/BasicLayout.vue` 的菜单：
   - 第一项“首页”保留。
   - 之后，`menus` 里的每个节点渲染成一个 `a-sub-menu`：`key` 用节点的 `key`，标题用 `displayName`，图标按节点的 `icon` 名字从 `@ant-design/icons-vue` 里取，取不到就用 `AppstoreOutlined`。
   - 每个子节点渲染成一个 `a-menu-item`，`key` 用子节点的 `path`。
   - 选中项跟随当前路由：`selectedKeys` 是 `[route.path]`。
   - 所有分组默认展开，用户可以手动收起。
4. `src/pages/ModelListPage.vue`：用 `defineProps<{ model: string }>()` 接收模型名，暂时只显示一个 `a-empty`，描述文字是“模型 xxx 的列表页将在任务 F2 实现”，其中 xxx 是模型名。
5. 任务完成后，另外生成 `docs/decisions/007-前端动态路由怎么做.md`：按第四部分的决策记录模板，写清两个候选方案（一条带参数的固定路由 `/app/:model`；按菜单用 `addRoute` 逐个注册）各自的做法、好处、代价，以及本项目选后者的理由。“讨论记录”和“代价和反思”两节留空，由用户自己填。

## F2 通用列表页

### 要实现的（AI 读）

新建 `src/stores/model.ts`、`src/components/fields/display.ts`、`src/components/ModelTable.vue`；修改 `src/pages/ModelListPage.vue`。

1. `src/stores/model.ts` 导出 `useModelStore`：
   - `get(name)`：返回 `Promise<ModelDef>`。第一次调用 `metaApi.model(name)`，结果按模型名缓存，之后直接返回缓存。
   - `invalidate(name?)`：清掉一个模型的缓存；不传参数时清空全部。
2. `src/components/fields/display.ts` 导出：
   - `SYSTEM_FIELD_TITLES`：`{ id: 'ID', created_at: '创建时间', updated_at: '修改时间' }`。
   - `displayValue(field: FieldDef | undefined, value: unknown): string`，规则：
     - 值是 `null`、`undefined` 或空字符串：返回 `—`。
     - 没有字段定义（系统字段）：返回 `String(value)`。
     - `enum`：返回选项里对应的 `label`，找不到就返回原值。
     - `boolean`：返回“是”或“否”。
     - `manyToOne`：值是 `{ id, label }`，返回 `label`。
     - `decimal`：最多保留字段 `scale` 位小数（默认 4），去掉末尾多余的 0。
     - 其它：返回 `String(value)`。
3. `src/components/ModelTable.vue` 是通用的“搜索区 + 工具栏 + 表格”，属性：

   ```ts
   defineProps<{
     /** 模型名 */
     model: string
     /** 固定的过滤条件：每次查询都带上，用户看不到也改不了。任务 F4 的子表会用 */
     fixedFilters?: Filter[]
     /** 不显示的列，同时也不出现在搜索区。任务 F4 的子表会用 */
     hiddenColumns?: string[]
     /** 新建记录时固定带上的值。任务 F3 会把它传给表单 */
     presetValues?: DataRecord
   }>()
   ```

   - 用 `useModelStore().get(model)` 取模型定义。`model` 变化时重新加载，并重置搜索条件、排序和页码。
   - **列**：取 `views.list.columns`，去掉 `hiddenColumns` 里的，去掉既不是模型字段也不是系统字段的。列标题用字段的 `displayName`，系统字段用 `SYSTEM_FIELD_TITLES`。单元格文字用 `displayValue`；`enum` 和 `boolean` 用 `a-tag` 包起来，`boolean` 为“是”时用绿色。除了 `text`、`manyToOne` 类型，其它列都可以点列头排序。
   - **操作列**：放在最后，有“编辑”（链接样式的按钮）和“删除”（用 `a-popconfirm` 确认）。
   - **搜索区**：取 `views.list.searchFields`，去掉 `hiddenColumns` 里的。每个字段按类型选控件和比较方式：

     | 字段类型 | 控件 | 发给接口的条件 |
     |---|---|---|
     | `string`、`text` | 输入框 | `like` |
     | `enum` | 下拉框，可清空 | `eq` |
     | `boolean` | 下拉框，选项为“是”“否”，可清空 | `eq`，值是 `true` 或 `false` |
     | `integer`、`decimal` | 数字输入框 | `eq` |
     | `date`、`datetime` | 日期范围选择 | 两个条件：`ge` 起始和 `le` 结束。`date` 用 `YYYY-MM-DD`；`datetime` 的起始补 ` 00:00:00`，结束补 ` 23:59:59` |
     | `manyToOne` | 本任务先跳过，任务 F4 再做 | |

     没填的条件不发送。有“查询”按钮（回到第 1 页再查）和“重置”按钮（清空条件再查）。一个搜索字段都没有时，不显示搜索区。
   - **查询**：调用 `dataApi.search(model, { page, size, filters, sort })`，`filters` 是 `fixedFilters` 加上搜索区的条件。每页条数初始值用 `views.list.pageSize`，没有就用 10。分页器显示总条数，可以切换每页 10、20、50 条。点列头排序时传 `sort: [{ field, order }]`，取消排序时不传 `sort`。
   - **工具栏**：右侧放“新增”按钮（主按钮样式）。本任务里，点“新增”和“编辑”只弹一条提示“表单在任务 F3 实现”。
   - **删除**：调用 `dataApi.remove`。成功后提示“已删除”并重新查询；如果当前页已经没有数据而且不是第 1 页，回到上一页。失败时不用再弹提示，列表保持不变。
   - 查询期间表格显示加载状态。表格的 `row-key` 用 `id`。
   - 用 `defineExpose` 暴露一个 `reload()` 方法，供外部刷新当前页。
4. `src/pages/ModelListPage.vue` 改成只渲染 `<ModelTable :model="model" />`。

### 你来验收（人做）

1. 字段输入组件，统一的属性和事件：

   ```ts
   defineProps<{ modelValue: unknown; field: FieldDef; disabled?: boolean }>()
   ```

   | 文件 | 用于的字段类型 | 做法 |

   | `StringField.vue` | `string` | `a-input`，最大长度用字段的 `length`（默认 255）。清空时发出 `null`，不要发空字符串 |

   | `EnumField.vue` | `enum` | `a-select`，选项来自字段的 `options`。字段不是必填时可以清空 |

2. `src/components/fields/index.ts` 导出字段类型到组件的注册表：

   ```ts
   export const fieldComponents: Partial<Record<FieldType, Component>> = {
     string: StringField,
     text: TextField,
     integer: NumberField,
     decimal: NumberField,
     boolean: BooleanField,
     date: DateField,
     datetime: DateField,
     enum: EnumField,
   }
   ```

   ```ts
     open: boolean

     recordId?: number | null
     /** 固定带上的值：对应的字段不显示在表单里，提交时带上 */
   ```

````markdown
## 通用约定

- 所有接口以 `/api` 开头，请求体和响应体都是 UTF-8 的 JSON。
- 本地地址：后端 `http://localhost:8200`，前端 `http://localhost:5173`。开发时前端把 `/api` 代理到后端，所以前端代码里只写 `/api/...`。

### 响应格式

成功时 HTTP 状态码是 200：

```json
{ "code": 0, "message": "ok", "data": {} }
```

失败时 HTTP 状态码表示错误大类，响应体格式不变：

```json
{ "code": 40900, "message": "物料编码已存在", "data": { "fieldErrors": { "code": "物料编码已存在" } } }
```

| HTTP 状态码 | code | 含义 |
|---|---|---|
| 400 | 40000 | 请求参数或数据校验不通过 |
| 404 | 40400 | 模型、记录或服务不存在 |
| 409 | 40900 | 冲突：名称重复、违反唯一约束、数据被别处引用 |
| 500 | 50000 | 系统错误 |

`data.fieldErrors` 只在错误能定位到具体字段时出现，键是字段名，值是给用户看的提示。前端把它显示在对应的表单项下面；没有 `fieldErrors` 时，用 `message` 弹一个全局提示。

### 命名

- 元模型 JSON 的键用 camelCase，例如 `displayName`、`searchFields`。
- 模块名、模型名、字段名、服务名统称“标识”，必须匹配 `^[a-z][a-z0-9_]{0,29}$`（小写字母开头，只含小写字母、数字、下划线，最长 30 位）。标识创建后不能改。
- 业务数据记录的键就是字段名，例如 `{ "code": "M-0001", "safety_stock": 10 }`。
````

文件 `docs/contract/meta-model.md`：

````markdown
# 元模型格式

元模型是“描述业务模型的数据”。开发者在设计器里定义它，平台读它来建表、提供接口、渲染页面。课题要求的“定义模型、属性、服务、视图”，对应下面的 `ModelDef`、`FieldDef`、`ServiceDef`、`ViewsDef`。

和课堂上的 IIDP 对照：

| 这里的元模型 | IIDP 里的写法 |
|---|---|
| `ModelDef` 的 `name`、`displayName`、`description` | `@Model(name = ..., displayName = ..., description = ...)` |
| `FieldDef` | `@Property(displayName = ...)` |
| `type: "manyToOne"` | `@ManyToOne` 加 `@JoinColumn` |
| `ServiceDef` | 模型类里写的服务方法 |
| `ViewsDef` | 视图 JSON |

区别在于：IIDP 把这些信息写在 Java 注解里，编译后才生效；这里把它们存成数据，运行时就能改。

完整例子见 [samples/mes.json](samples/mes.json)。

## 模块 ModuleDef

模块用来给模型分组，对应左侧菜单的一级目录。

| 键 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | 标识 |
| `displayName` | string | 是 | 显示名 |
| `icon` | string | 否 | Ant Design 图标的组件名，例如 `AppstoreOutlined` |
| `sort` | number | 否 | 菜单排序，小的在前，默认 100 |

## 模型 ModelDef

| 键 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | 标识 |
| `displayName` | string | 是 | 显示名 |
| `description` | string | 否 | 说明 |
| `module` | string | 是 | 所属模块的 `name` |
| `showInMenu` | boolean | 否 | 是否出现在菜单里，默认 `true`。只作为子表使用的模型设为 `false` |
| `sort` | number | 否 | 在模块内的排序，默认 100 |
| `fields` | FieldDef[] | 是 | 至少一个字段 |
| `services` | ServiceDef[] | 否 | 默认空数组 |
| `views` | ViewsDef | 否 | 请求里可以不传，后端会生成默认视图。**后端返回的模型定义里 `views` 一定是完整的** |
| `tableName` | string | 只读 | 后端生成的表名，请求里传了也会被忽略 |

后端返回模型定义时，会把 `showInMenu`、`sort`、`services`、`views` 这些有默认值的键都补齐，前端不用自己处理缺省。

每个模型自动带三个系统字段，不用也不能在 `fields` 里定义：

| 字段名 | 类型 | 说明 |
|---|---|---|
| `id` | integer | 主键，自增 |
| `created_at` | datetime | 创建时间 |
| `updated_at` | datetime | 最后修改时间 |

## 字段 FieldDef

| 键 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | 标识，不能和系统字段重名 |
| `displayName` | string | 是 | 显示名 |
| `type` | string | 是 | 字段类型，见下表 |
| `required` | boolean | 否 | 必填，默认 `false` |
| `unique` | boolean | 否 | 值不能重复，默认 `false` |
| `readonly` | boolean | 否 | 表单里只读，默认 `false`。用于由服务自动填写的字段，例如自动生成的编码 |
| `defaultValue` | 与类型对应 | 否 | 新建记录时的默认值 |
| `length` | number | 否 | 只用于 `string`，默认 255 |
| `precision`、`scale` | number | 否 | 只用于 `decimal`，默认 18 和 4 |
| `options` | `{ value, label }[]` | `enum` 必填 | 枚举的选项 |
| `relation` | RelationDef | 关联类型必填 | 见下面的“关联” |

### 字段类型

| `type` | 含义 | 记录里的 JSON 值 | 默认的表单组件 |
|---|---|---|---|
| `string` | 单行文本 | 字符串 | 输入框 |
| `text` | 多行文本 | 字符串 | 多行输入框 |
| `integer` | 整数 | 数字 | 数字输入框 |
| `decimal` | 小数 | 数字 | 数字输入框 |
| `boolean` | 是或否 | `true` / `false` | 开关 |
| `date` | 日期 | `"2026-11-14"` | 日期选择 |
| `datetime` | 日期时间 | `"2026-11-14 09:30:00"` | 日期时间选择 |
| `enum` | 单选 | 选项的 `value`（字符串） | 下拉框 |
| `manyToOne` | 多对一 | 响应里是 `{ "id": 3, "label": "螺丝 M3" }`，请求里传 `3` | 可搜索的下拉框 |
| `oneToMany` | 一对多 | 不出现在记录里 | 表单里的子表标签页 |

没有值的字段在响应里是 `null`。

### 关联 RelationDef

多对一，例如“产品 BOM”里的“物料”字段：

```json
{ "name": "material", "displayName": "物料", "type": "manyToOne", "required": true,
  "relation": { "model": "material", "displayField": "name" } }
```

- `model`：指向哪个模型。
- `displayField`：用目标模型的哪个字段当显示文字，也就是响应里的 `label`。
- 请求里传目标记录的 `id`。为了让前端能把读到的记录改完直接传回来，后端也接受 `{ "id": 3, "label": "..." }` 这种形式，只取其中的 `id`。

一对多，例如“产品”里的“BOM 明细”字段：

```json
{ "name": "bom_lines", "displayName": "BOM 明细", "type": "oneToMany",
  "relation": { "model": "product_bom", "mappedBy": "product" } }
```

- `model`：子表模型。
- `mappedBy`：子表模型里指回本模型的那个 `manyToOne` 字段名。
- 一对多字段不占数据库列，也不出现在记录里。前端要显示子表时，对子表模型调用查询接口，条件是 `mappedBy` 字段等于当前记录的 `id`。子表记录的增删改直接调子表模型的数据接口。

## 服务 ServiceDef

增删改查是每个模型自带的内置服务，不用定义。这里定义的是开发者自己写的脚本服务。

| 键 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | 标识 |
| `displayName` | string | 是 | 显示名，手动服务用它当按钮文字 |
| `trigger` | string | 是 | 什么时候执行，见下表 |
| `scope` | string | 否 | 只用于 `manual`：`record` 针对一条记录，`model` 不针对具体记录。默认 `record` |
| `script` | string | 是 | 脚本内容 |
| `enabled` | boolean | 否 | 默认 `true` |

| `trigger` | 执行时机 |
|---|---|
| `manual` | 用户点按钮，或者调用服务接口 `/api/svc/{model}/{service}` |
| `beforeCreate` | 新建记录、写入数据库之前。脚本可以修改将要保存的记录 |
| `afterCreate` | 新建记录、写入数据库之后 |
| `beforeUpdate` | 修改记录、写入数据库之前 |
| `afterUpdate` | 修改记录、写入数据库之后 |
| `beforeDelete` | 删除记录之前。脚本可以阻止删除 |

前端的显示规则：`manual` 且 `scope` 为 `record` 的服务，显示成列表每一行操作列里的按钮；`scope` 为 `model` 的显示成列表上方工具栏的按钮。其它触发方式的服务不显示按钮。

脚本用什么语言、脚本里能访问哪些变量，由后端在决策记录 006 里确定，定下来之后补到这份文档里。`samples/mes.json` 里的脚本目前是文字描述，届时一起改写。

## 视图 ViewsDef

```json
{
  "list": {
    "columns": ["code", "name", "category"],
    "searchFields": ["code", "name"],
    "defaultSort": { "field": "created_at", "order": "desc" },
    "pageSize": 10
  },
  "form": {
    "groups": [
      { "title": "基本信息", "columns": 2, "fields": ["code", "name", "category"] }
    ],
    "tabs": [
      { "title": "BOM 明细", "field": "bom_lines" }
    ]
  }
}
```

| 键 | 说明 |
|---|---|
| `list.columns` | 列表显示哪些字段，按数组顺序排列 |
| `list.searchFields` | 搜索区有哪些字段 |
| `list.defaultSort` | 默认排序，`order` 是 `asc` 或 `desc` |
| `list.pageSize` | 每页条数，默认 10 |
| `form.groups` | 表单分组。`columns` 是每行放几个字段（1 到 4），`fields` 是这一组里的字段 |
| `form.tabs` | 表单下方的子表标签页，`field` 必须是一个 `oneToMany` 字段 |

视图里出现的字段名都必须是这个模型已有的字段，系统字段也可以用。

### 默认视图

模型定义里没有传 `views` 时，后端按下面的规则生成：

- `list.columns`：除 `text` 和 `oneToMany` 以外的所有字段，按定义顺序。
- `list.searchFields`：前 3 个 `string` 或 `enum` 字段。
- `list.defaultSort`：按 `created_at` 倒序。
- `form.groups`：一个标题为“基本信息”的分组，每行 2 个，包含除 `oneToMany` 以外的所有字段。
- `form.tabs`：每个 `oneToMany` 字段一个标签页，标题用字段的显示名。
````

````markdown
## 元模型接口

### `GET /api/meta/menus`

返回菜单树。一级是模块，二级是模块里 `showInMenu` 为 `true` 的模型，都已经排好序。没有可显示模型的模块不返回。

```json
[
  {
    "key": "mes", "displayName": "生产管理", "icon": "AppstoreOutlined",
    "children": [
      { "key": "material", "displayName": "物料", "model": "material", "path": "/app/material" },
      { "key": "product", "displayName": "产品", "model": "product", "path": "/app/product" }
    ]
  }
]
```

前端按叶子节点的 `path` 和 `model` 动态注册路由。`path` 固定是 `/app/` 加模型名。

### `GET /api/meta/modules`

返回 `ModuleDef[]`，按 `sort` 排序。

### `PUT /api/meta/modules/{name}`

新建或修改模块，请求体是 `ModuleDef`，返回保存后的 `ModuleDef`。路径里的 `name` 和请求体里的 `name` 不一致时返回 400。

### `DELETE /api/meta/modules/{name}`

删除模块。模块下还有模型时返回 409。

### `GET /api/meta/models`

返回全部模型的完整定义 `ModelDef[]`。

### `GET /api/meta/models/{name}`

返回一个模型的完整定义 `ModelDef`。不存在时返回 404。

### `POST /api/meta/models`

新建模型。请求体是 `ModelDef`，返回保存后的 `ModelDef`。成功后数据表已经建好，数据接口立刻可用。

- 校验不通过返回 400。例如标识不合规则、字段重名、`enum` 没有 `options`、关联指向不存在的模型、视图里用了不存在的字段。
- 同名模型已存在返回 409。

### `PUT /api/meta/models/{name}`

修改模型。请求体是完整的 `ModelDef`，返回保存后的 `ModelDef`。

- 新增的字段立刻可用，已有数据在新字段上的值是默认值或 `null`。
- 从 `fields` 里去掉的字段不再显示，也不能再读写。数据库里的列和数据是否保留，由后端在决策记录 005 里确定。
- 不允许修改已有字段的 `type`，返回 400。

### `DELETE /api/meta/models/{name}`

删除模型。模型被其它模型的关联字段引用时返回 409。

### `GET /api/meta/export`

把全部模块和模型导出成一个 `MetaBundle`。

### `POST /api/meta/import`

导入一个 `MetaBundle`。包里的模块和模型，不存在的新建，已存在的按修改处理。整个包要么全部成功，要么全部不生效。

```json
{ "modules": 2, "models": 4 }
```

返回的是这次处理了多少个模块和模型。

## 数据接口

`{model}` 是模型名。模型不存在时所有数据接口都返回 404。

记录的格式：键是字段名，值的格式见 [meta-model.md 的字段类型表](meta-model.md#字段类型)。响应里的记录总是带 `id`、`created_at`、`updated_at`。

```json
{
  "id": 7,
  "product": { "id": 1, "label": "电动螺丝刀" },
  "material": { "id": 3, "label": "螺丝 M3" },
  "quantity": 12,
  "created_at": "2026-11-14 10:20:30",
  "updated_at": "2026-11-14 10:20:30"
}
```

### `POST /api/data/{model}/search`

分页查询。请求体里的每一项都可以不传。

```json
{
  "page": 1,
  "size": 10,
  "filters": [
    { "field": "name", "op": "like", "value": "螺丝" },
    { "field": "category", "op": "eq", "value": "raw" }
  ],
  "sort": [ { "field": "created_at", "order": "desc" } ]
}
```

- `page` 从 1 开始，默认 1。`size` 默认 10，最大 200。
- 多个 `filters` 之间是“并且”的关系。
- 不传 `sort` 时用模型视图里的 `defaultSort`。
- `filters` 和 `sort` 里的 `field` 必须是这个模型的字段或系统字段，否则返回 400。

| `op` | 含义 | `value` |
|---|---|---|
| `eq` | 等于 | 单个值 |
| `ne` | 不等于 | 单个值 |
| `like` | 包含 | 字符串 |
| `gt`、`ge`、`lt`、`le` | 大于、大于等于、小于、小于等于 | 单个值 |
| `in` | 在列表中 | 数组 |

对 `manyToOne` 字段过滤时，`value` 传目标记录的 `id`。

响应：

```json
{ "records": [ /* 记录 */ ], "total": 37, "page": 1, "size": 10 }
```

### `GET /api/data/{model}/{id}`

返回一条记录。不存在时返回 404。

### `POST /api/data/{model}`

新建记录。请求体是记录，不用带系统字段，带了会被忽略。返回保存后的完整记录。

- 没传的字段取默认值，没有默认值的是 `null`。
- 必填字段没有值、值的类型不对、枚举值不在选项里：返回 400，带 `fieldErrors`。
- 违反唯一约束：返回 409，带 `fieldErrors`。
- 请求体里有模型没定义的字段：返回 400。

### `PUT /api/data/{model}/{id}`

修改记录。请求体只需要带要改的字段，没带的字段保持原值。返回修改后的完整记录。校验规则和新建相同。

### `DELETE /api/data/{model}/{id}`

删除记录。记录被其它记录通过 `manyToOne` 引用时返回 409，`message` 里说明被谁引用。

### `GET /api/data/{model}/options?keyword=螺丝&limit=20`

给 `manyToOne` 的下拉框用。`keyword` 可选，按显示字段模糊匹配；`limit` 默认 20，最大 100。

```json
[ { "value": 3, "label": "螺丝 M3" }, { "value": 4, "label": "螺丝 M4" } ]
```

`label` 取哪个字段：调用方用查询参数 `displayField` 指定，前端应该总是把关联字段定义里的 `relation.displayField` 传过来。没有指定时，后端用这个模型第一个 `string` 类型的字段。

## 服务接口

### `POST /api/svc/{model}/{service}`

调用一个 `trigger` 为 `manual` 的服务。

```json
{ "id": 1, "params": {} }
```

- `id`：`scope` 为 `record` 的服务必填，是要操作的记录；`scope` 为 `model` 的服务不用传。
- `params`：传给脚本的参数，可以不传。

`data` 是脚本的返回值，可以是任何 JSON 值。例如编码规则的 `generate` 服务返回 `"MAT-20261114-0001"`。

- 模型或服务不存在、服务不是 `manual`：返回 404。
- 脚本执行出错：返回 400，`message` 是出错原因。

## AI 接口（加分项）

### `POST /api/ai/generate`

```json
{ "prompt": "我要管理供应商，记录名称、联系人、电话和信用等级" }
```

返回一个 `MetaBundle`。**这个接口只生成，不保存。** 前端把结果展示给用户，用户确认或修改后，再调用 `POST /api/meta/import` 让它生效。

没有配置大模型的 API key 时返回 400，`message` 说明没有配置。
````

````ts
export type FieldType =
  | 'string'
  | 'text'
  | 'integer'
  | 'decimal'
  | 'boolean'
  | 'date'
  | 'datetime'
  | 'enum'
  | 'manyToOne'
  | 'oneToMany'

export interface EnumOption {
  value: string
  label: string
}

export interface RelationDef {
  /** 关联到哪个模型 */
  model: string
  /** manyToOne 专用：用目标模型的哪个字段当显示文字 */
  displayField?: string
  /** oneToMany 专用：子表模型里指回本模型的 manyToOne 字段名 */
  mappedBy?: string
}

export interface FieldDef {
  name: string
  displayName: string
  type: FieldType
  required?: boolean
  unique?: boolean
  readonly?: boolean
  defaultValue?: unknown
  /** string 专用 */
  length?: number
  /** decimal 专用 */
  precision?: number
  /** decimal 专用 */
  scale?: number
  /** enum 必填 */
  options?: EnumOption[]
  /** manyToOne、oneToMany 必填 */
  relation?: RelationDef
}

export type ServiceTrigger =
  | 'manual'
  | 'beforeCreate'
  | 'afterCreate'
  | 'beforeUpdate'
  | 'afterUpdate'
````

````ts
import axios from 'axios'
import type { AxiosError, AxiosRequestConfig } from 'axios'
import { message } from 'ant-design-vue'

import { mockAdapter } from '@/mock'
import type { ApiResult } from '@/types/api'

/** 为 true 时所有接口走前端内存 mock，由 .env.development 里的 VITE_USE_MOCK 控制 */
export const useMock = import.meta.env.VITE_USE_MOCK === 'true'

/**
 * 接口返回的错误。
 * fieldErrors 的键是字段名：表单页捕获这个错误后，把提示显示在对应的表单项下面。
 */
export class ApiError extends Error {
  code: number
  status: number
  fieldErrors: Record<string, string>

  constructor(text: string, code: number, status: number, fieldErrors: Record<string, string>) {
    super(text)
    this.name = 'ApiError'
    this.code = code
    this.status = status
    this.fieldErrors = fieldErrors
  }
}

const http = axios.create({ baseURL: '/api', timeout: 15000 })

if (useMock) {
  http.defaults.adapter = mockAdapter
}

function readFieldErrors(data: unknown): Record<string, string> {
  if (data && typeof data === 'object' && 'fieldErrors' in data) {
    const fieldErrors = (data as { fieldErrors: unknown }).fieldErrors
    if (fieldErrors && typeof fieldErrors === 'object') {
      return fieldErrors as Record<string, string>
    }
  }
  return {}
}

http.interceptors.response.use(
  (response) => response,
  (error: AxiosError<ApiResult<unknown> | undefined>) => {
    const status = error.response?.status ?? 0
    const body = error.response?.data
    const hasBody = body !== null && typeof body === 'object'
    const text = hasBody
      ? body.message
      : status === 0
        ? '连不上后端，请确认后端已经启动'
        : `请求失败（HTTP ${status}），请确认后端已经启动`
    const fieldErrors = hasBody ? readFieldErrors(body.data) : {}
    // 能定位到字段的错误交给表单显示，其它错误弹全局提示
    if (Object.keys(fieldErrors).length === 0) {
      message.error(text)
    }
    return Promise.reject(new ApiError(text, hasBody ? body.code : -1, status, fieldErrors))
  },
)

/** 发请求并取出响应里的 data。失败时抛 ApiError。 */
export async function request<T>(config: AxiosRequestConfig): Promise<T> {
  const response = await http.request<ApiResult<T>>(config)
  return response.data.data
}
````
